# 按 Agent Run 业务风险分配验证责任

测试首先证明 Agent Run 能正确开发、审核、修复、集成、发布、批准和收尾，
以及中断后继续原工作。Ticket、Parent-only、Parent→Final 保留各自的代表旅程与独有规则。
共享规则不在每种交付形式的完整旅程中重复展开全部参数组合。

采用三个有明确职责的层次：

- 业务旅程验证阶段之间的连接、重要失败恢复和最终成果，保留真实公开入口、Core 与必要资源。
- 推进规则直接调用生产逻辑；依赖事务关系时用真实 Core/SQLite，避免无关 Git、Host 和历史交付前缀。
- 资源与接口合同以有限真实 Git、进程、CLI、安装和存储验证输入、输出、授权及故障边界。

允许删除重复、低价值或绑定实现的测试，不要求逐条保留历史断言。
删除或迁移时说明重要业务风险现在由哪个层次负责；测试数量不作为质量指标。
例如文本格式组合由生产渲染器验证，真实旅程负责确认正确材料确实进入渲染器。
测试替身只提供外部事实，不能实现另一套业务选择或把自身输出当作唯一预期答案。

生产模块按实际职责拆分，真实 Core 和轻测试共用同一决策函数。
当下授权、并发归属、事务提交和未知写入对账继续在原真实边界核验。
不缓存可变授权，不削弱持久化或以共享可变前置状态换取速度。
普通场景不采集无人使用的状态快照；诊断显式启用。

总代码、概念和维护负担应减少；删除被替代路径，避免通用场景框架与兼容转发层。
测试运行采用一个完整集合：本地 6 worker；CI 总计最多 2 worker，环境与必要外围检查串行复用。
时间上限与计量范围见[测试指南](../agents/testing.md)。预算和正确性分别验收，任一未满足都不算完成。
