# 以业务对象为保存边界，优先降低存储表示复杂度

当前 SQLite 实现以通用节点、快照引用和多种投影支持局部更新，也引入了额外的重建、证明和同步责任。持久化以明确业务对象及其有界当前状态为读写单位，允许一个字段变化时重新编码所属对象的小份当前状态；历史和固定大材料独立组织，不随小更新处理完整 Run。接受对象内部有限的额外读写，以降低实现和维护成本，不将字段级最小写入作为默认目标。

核心状态采用明确的关系表与列：身份、阶段、暂停条件、执行归属、预算和结果引用等不放入通用 JSON 正文，也不在列与正文中重复保存。JSON 仅用于确需保留原格式的材料及公开接口输出；材料保存一次并以准确身份引用，接口输出由查询按需生成。接受按领域演进维护明确结构的成本，以减少隐含字段、重复事实和解析校验；不为消除材料中的 JSON 而逐字段拆解报告。对象级保存不要求整行重写，仍以关联业务变化为事务边界。

资源限制改为按当前记录、单份材料、查询批次及响应、实际存储总量分别约束，取代按旧完整 Run JSON 重复展开后精确计算 4 MiB 的目标规则。保留内存与存储有界、必要证据完整、超限明确报错的要求；不以静默截断、删除必要历史或重置预算满足限额。具体额度与计量实现依据实际数据设计并验证，公开输出字段、身份与语义继续保留。

这延续 ADR 0026、0027 的 SQLite 和对象归属方向；并发授权、关联更新原子性、故障隔离、准确退出与显式恢复保证继续有效。新增缓存或特殊编码应与直接对象存储基线比较后决定。具体表、列、关系及状态精简由实际消费点和恢复边界决定；本决策不表示替代实现或性能收益已经验证。Task Control 同库的独立取舍见 [ADR 0029](0029-unified-control-and-business-storage.md)。

新结构只支持按新协议创建的 Run，明确不兼容或迁移既有 JSON Run 及此次调整前的 SQLite Run，保留旧文件和成果。接受既有 SQLite Run 不能直接由新协议续接的代价，以避免维护两套持久化表示与迁移逻辑；旧 Runner 的使用条件另行核验，不承诺自动恢复。此存储协议决定不自动授权改变公开 CLI 或机器输出合同。
