# Runner 独立管理交付工作区

Runner 曾把命令启动时的用户仓库作为交付工作区，向其中写入状态、分支和 worktree 元数据。合并后仅移动已检出分支的引用，还可能使文件和索引与该引用不一致。用户仓库应由维护者自行管理，交付权限不包含更新它的授权。

## 决策

Runner 只读识别用户仓库的远端，也支持在任意目录通过 `--repo` 指定目标；实际交付从远端建立独立克隆，不共享用户仓库的 Git 元数据。只使用远端已推送内容，Git 和远端交付仍沿用原有授权规则。

同一用户在本机对同一 Repository/Parent 复用唯一未完成 Delivery Run、Executor 槽位和 Action 准入门。不同启动目录和用户 clone 不产生新任务身份，不同 Parent 仍可并行。这取代 [ADR 0010](0010-task-scoped-run-executor.md) 中以用户仓库根区分任务、由维护者协调不同 clone 的约定；不扩展为跨用户或跨主机协调。

长期数据统一放在 `$XDG_DATA_HOME/agent-run/`，默认 `~/.local/share/agent-run/`，包括安装快照、独立仓库、运行状态、日志和定位索引；路径规则由一个入口定义。配置与临时运行文件继续按生命周期分开。安装、卸载和任务清理各自只管理其负责的内容，卸载保留任务数据。

成功或显式放弃后清理可安全删除的受管 worktree，保留运行记录；失败、暂停和人工等待保留开发现场。丢弃未提交成果仍需额外显式授权，不按时间自动删除。Worker 只获得本轮 checkout 所需的访问，Runner 安装和控制数据继续隔离。

## 后果

用户自行拉取远端交付结果；Runner 不再修改用户仓库的文件、索引、引用或 Git 元数据。目录按需创建，无法创建时明确失败，不回退到用户仓库。

独立克隆增加一份受管 Git 数据，换取清晰的所有权、恢复和清理边界。仅把 worktree 移到仓库外仍会共享用户 `.git`，不足以满足该边界，因此不采用。

旧任务及旧位置的数据不纳入此次变更：不迁移、恢复或清理，也不要求升级前先收尾。
