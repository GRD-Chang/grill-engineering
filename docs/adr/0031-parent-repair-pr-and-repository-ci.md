# Parent 修复通过 PR 进入 Run，CI 去重由仓库独立负责

## 决定与实施状态

本决定已确认，通用 Runner 的修复 PR 路径尚未实施。当前 Runner 仍采用 [ADR 0025](0025-parent-repair-without-internal-pr.md)
的直接更新 Run Branch 路径；不能把本文或领域术语的更新当成已交付证明。

完整 Parent 的修复及需要写入 Run Branch 的整体集成成果，经独立整体验收后，
由程序发布为指向 Run Branch 的 Run Repair PR。程序读取目标仓库的 GitHub 检查要求，
只有准确当前成果满足门禁后才能合入；不要求规则豁免，不保留直接推送修复成果的旁路。
这恢复正常 PR 的服务端准入和合入记录，解决受保护 Run Branch 拒绝未经前置检查更新的冲突。

修复 PR 合入后，程序核验实际成果、基线与需求是否仍符合候选验收。
仍适用的验收可以提升使用，不能仅因新的 merge SHA 重跑相同审核，也不能仅凭相同 tree
复用所有授权；变化的组合须补足验证。整体验收通过且无需更新 Run 的现有成果直接进入最终 Run PR；
若机械集成产生需要写入 Run 的新成果，仍经修复 PR 进入，不因没有 Findings 省略合法写入路径。
最终 Run PR 的 CI 失败仍进入 Parent 修复。最终 Run PR 始终承担默认分支检查与人工批准，
合入前再次核验准确版本、验收和检查。

修复继续使用 Parent 的工作身份、累计额度与既有恢复边界，不因创建或合并修复 PR 重置预算、
轮换工作或增加重复审核。恢复必要的分支、PR、CI 等待与合入对账，不恢复历史完整嵌套交付流程、
旧 Engine 或旧协议。结果未知的写入先按原意图对账，不盲目重放；现有旧 Run 兼容边界不扩大。

## CI 配置归属与取舍

GitHub 的仓库规则仍是合入前检查要求的来源。Runner 不增加用户维护的检查清单，
不依赖特定 Workflow 或去重 Action；未配置必过检查时沿用既有合同，不宣称 CI 已经通过。
仓库自行决定检查内部是否执行测试或复用仍适用的完整成功结果。

维护工作区的私有 CI 去重已独立交付，采用现成 Action 提供候选并校验原始完整证据；
公开产品 Workflow 与其他接入仓库不因此改变。每张 PR 保留自己的真实门禁，
只有成果、执行输入及所需覆盖仍适用时才避免重复测试，并引用原始成功运行；
证据缺失或不适用时正常执行。最终有效组合进入 main 后不重复同一套完整测试，
必要的主干任务单独保留。该优化既不是其他仓库接入 Runner 的前提，也不阻塞修复 PR 的交付。

代价是重新维护修复分支和 PR 的必要生命周期；相比给程序身份豁免，GitHub 可以继续独立约束
修复与 Ticket 的准入。重复测试成本通过仓库 CI 处理，不用降低通用 Runner 的交付门禁换取效率。

本决定取代 ADR 0025 中取消修复 PR、由程序直接写入 Run Branch 的条款，
并调整 [ADR 0024](0024-orchestration-responsibility-separation.md) 中相应路径。
其余职责划分、语义工作身份、预算、准确写入与最终人工批准合同继续有效。
