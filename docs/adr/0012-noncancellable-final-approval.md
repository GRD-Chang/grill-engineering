# 最终批准执行期间不可取消，失败后显式恢复

2026-09-13 的真实运行讨论确认：维护者执行 `approve`，是在批准当前版本的最终交付。若命令只保存批准便报告成功，或者随后允许 `stop` 将合并与收尾拆开，用户无法从这次操作判断交付是否完成。本决策已确认，现有实现是否完整满足仍需后续验证；证据和讨论见[需求记录](../research/2026-09-13-e2e-diagnostics-history-requirements.md)。

本 ADR 有限修订 [ADR 0010](0010-task-scoped-run-executor.md) 中 `approve` 的动作完成、准入释放与 CLI 返回边界，并适用于显式 `resume` 正在继续原最终批准操作的情形；其他生命周期动作沿用既有规则。

最终批准安全接受后，最终条件复核、合并、关闭整体需求 Issue 与必要清理构成一次不可取消的操作。执行期间不接受 `stop`、`abandon` 或其他竞争的生命周期动作，不排队、不增加优先级。拒绝时明确说明“正在执行最终批准，暂不支持停止”等实际原因；`status` 和 `history` 仍可读取进度。正常流程在合并前检查通过或确认未配置强制检查后等待人工批准；批准后的再次读取是确认条件仍有效，不是重新触发 CI。

这一次操作占用 Action Admission Gate，直到成功完成，或持久记录失败、超时、结果未知或原批准失效等不能继续的边界。不能只凭批准已保存或 Executor 已握手就释放准入；也不能在操作已结束后无限保留 `action_busy`。该业务边界不构成长时间持有 Task Control Lock 或其他共享状态锁的理由。

`approve` 默认通过可离开的 Action Completion Observation 等待实际结果后返回。成功回执表示最终交付与必要收尾已经完成；无法继续时报告已完成部分、未完成部分和当前允许的下一步，原批准仍适用的可恢复失败提供 `agent-run resume <parent-issue>`。关闭终端或 Ctrl-C 只停止观察，不撤销已接受操作，也不能报告交付成功。恢复原最终批准操作的 `resume` 使用相同完成边界，不改变普通 `resume` 的返回合同。

外部错误与等待采用既有有界处理，不因不可取消而无限重试或永久占用执行者。失败须保留原批准、已完成进度和准确故障事实；恢复前先确认旧执行者已结束，并依据远端权威事实确认实际结果：

- 尚未合并：重新核对原批准仍适用于当前版本、目标与需求，再继续合并。
- 合并结果未知：先查询确认是否已生效，不盲目重发合并请求。
- 已合并但关闭 Issue 或清理失败：只继续未完成的收尾，不重复开发、验收或合并。

事实未变时，恢复不要求再次 `approve`；head、base 或有效需求已变化时，仍按既有失效规则重新验收和批准。恢复不能扩大原批准范围，也不能为绕过遗留忙碌记录而删除控制事实、另建 Run 或启动第二个执行者。仅能确定操作结果、尚不能证明旧执行者退出时，仍不得启动后继执行者。

原最终批准操作的 approve 或恢复该操作的 resume 因崩溃遗留未收口 Action 时，`resume` 可在新动作准入前先对账这一原操作；必须先证明旧执行已结束并记录原 Action 的确定结果，再决定是否接受恢复动作，不要求操作者先重新输入 approve。该例外只服务于原最终批准操作的恢复；这类失败或超时由显式 resume 恢复，普通 run 不隐式继续最终批准。Action Application Receipt 只证明批准意图已保存，不能单独证明合并与收尾已完成或据此将整个批准操作标为成功。

这里的“原子”只表示操作者不能取消执行中的最终批准，不提供 GitHub 合并、Issue 关闭和本地清理跨系统的全成或全退保证。合并已经发生而收尾失败时，必须如实显示已合并，并允许恢复收尾，不自动回滚代码。

## Considered Options

- 批准保存后立即释放准入，允许 stop 中断后续交付：延续 ADR 0010 的原边界，但不符合此次确认的完整批准操作含义。
- 不可取消且任何失败都一直重试：会使外部故障变成永久忙碌；采用有界失败和显式恢复。
- 合并或收尾失败时全部回滚：外部系统没有共同事务，且撤销已合并代码需要新的业务决定，因此不采用。

## Consequences

操作者在最终批准执行期间不能立即停止该操作；查询与终端独立性仍保留。实现需核验准入、操作回执、失败持久化及三类恢复路径，不能仅修改 `action_busy` 文案便宣称完成。复用现有 RunDriver、Publisher 结果对账与 closeout 恢复机制，不新增队列、后台守护进程或第二套交付状态机。
