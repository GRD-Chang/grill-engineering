# 完整 Parent 的修复不再经过内部 Repair PR

完整 Parent 的 Findings 与 CI 修复进入 Parent 自身的开发、集成和发布循环，由程序准确更新 Run Branch，最终 Run PR 承担 Hosted CI 与人工批准门禁。取消内部 Repair PR 的文案、创建、CI 等待、合并对账，以及因其已合并而轮换修复 Job 的流程。修复仍有明确的工作身份、受管工作区、成果和历史。

这一决定减少 Parent 内部嵌套的完整交付生命周期，保留三个 Agent 角色、两个循环及 ADR 0024 的职责划分。代价是修复进入 Run Branch 前不再拥有独立 PR 的 CI 门禁、讨论页和服务端 PR 合并记录；Run Branch 可以包含尚未通过最终 CI 的修复版本。Ticket PR 的交付与 CI 不变，默认分支仍须经过有效完整验收、当前最终 PR 的必要检查及人工批准。

程序继续负责正式 Git/GitHub 写入，保存准确操作意图，维护必要祖先关系并核验实际写入结果；丢失响应先对账。候选验收只有在需求、基线、实际成果及预期合并结果等事实仍适用时复用，不能因去掉内部 PR 就省略核验。修复改变成果后重新核验相关证据与批准；额度归属、累计消费和恢复沿用已确定合同。

实施须核对最终 CI 的必要检查覆盖及 Run Branch 更新权限，不假定内部 PR 与最终 PR 的检查触发完全等价，不绕过仓库规则。更新权限或仓库规则不满足时沿用人工暂停及 resume 原则，不自动恢复已取消的内部 PR 流程。

本决定取代 ADR 0016、ADR 0023 中要求保留内部 Run Repair 分支/PR 独立交付流程的条款；受管开发工作区与必要的本地分支安排不因此取消。其余审核范围、预算、Git 祖先关系、最终合并和人工批准合同继续有效。新 Run 使用 `branch_authority_protocol=3`；不兼容读取所有旧 Run，不增加迁移或双流程兼容，拒绝继续不授权删除旧成果。未知推送先核验原操作的准确源、目标、候选和实际远端结果；权限或规则拒绝更新时保全工作并暂停，人工处理后通过 resume 继续原工作。

## 接入核验

最终 PR 的必要检查须按接入仓库的触发事件、目标分支、路径选择与准确 PR/head 核验；内部 PR 的同名检查不能替代。Run Branch 推送权限须同时核验实际 Runner 凭据和分支规则，仓库级写权限不代表能绕过 required checks。若新修复 head 无法满足现有 Run Branch 更新规则，程序保全成果并暂停，由维护者处理后 resume；本功能不自动修改规则。
