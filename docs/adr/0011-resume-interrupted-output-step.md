# 恢复中断的 Agent 工作，容量不足时持续自动续跑

Issue #205 与 #154 的讨论基于 #156 Run Branch 的 `120a0f2`。本 ADR 是已确认、尚待实现的目标合同；不表示该分支已完成这两个 Issue，也不表示 #156 已通过整体验收。

2026-09-08 按用户要求将两项需求完整合并到 Issue #154，作为唯一开发与验收任务；Issue #205 以重复任务关闭并保留事故与原规格。该关闭不表示功能已实现。

## 决策

### 两种 Resume 语义

Business Resume（业务恢复）处理明确的业务暂停：Human Blocker 需要回应或确认后继续；预算耗尽检查点需要维护者显式授权新的预算窗口。这些暂停是被识别并记录的业务结果，不等于执行中意外退出。

Execution Recovery（执行续接）处理已经获准但尚未完成的工作被异常打断：保留原 Thread、工作步骤、权限和预算继续执行。自动触发或人工触发不改变该语义；人工执行续接命令也不隐含授权新预算窗口。已有 Human Blocker、预算检查点或其他业务门禁不能被执行续接绕过，Agent 正常返回 blocker 后进程退出也不能触发异常自动续跑。

保留单一公开 `resume` 入口，不新增 `recover`。暂停原因、所需授权与后续执行动作分别建模，不把 Business Resume / Execution Recovery 直接固化为两套控制流程。人工 `resume` 在准入时根据准确状态绑定本次恢复对象、原因、授权与前置条件；重复附着原 Action 继续使用已接受的意图。执行时绑定失效即拒绝，不得把原工作的异常续接重新解释为开启预算窗口。预算检查点的状态提示与 Action 回执必须明确说明本次 Resume 将授权或已开启新窗口。

自动恢复仅进入无业务授权能力的执行续接路径，不模拟人工 CLI 命令，不调用可以解除 Human Blocker 或开启预算窗口的完整 Controller.resume 路径。人工与自动续接共享适用的 Thread 调用、权限核验、进程管理、持久化及既有 RunDriver；人工回应、中断续接和新窗口授权仍分别处理，不借本次变更另建通用恢复框架或复制执行循环。

Invocation Resume 只是调用层动作。执行续接的输入只服务于继续原先被中断的工作，继承既有角色、阶段与输出要求，不引入新任务或预算授权；JSON 修复仍携带原校验错误并保持只读。

### 异常与容量恢复

本次“异常”指 Codex 在执行中被意外杀死、进程异常退出或本轮因服务错误结束；JSON 已正常返回但校验不合格是输出校验失败，不是这里的进程异常。Resume 继续原 Thread 中尚未完成的工作，不重开业务尝试、不改变或重置 Development、Review、Publication 预算、Budget Window 或既有格式修复额度。2026-09-08 的后续澄清将模型容量不足从普通一次自动恢复限制中单独排除。

Executor 自身消失时，沿用 ADR 0010：状态查询只读核验准确 Host ownership；后续 lifecycle mutation 根据 Host、Run receipt 与 generation 对账，确认中断后保留 checkout、Candidate、Thread 与 Semantic Agent Attempt，等待维护者显式 `resume`。证据不足时 fail closed，不启动第二个 Worker。

Executor 仍存活且确认 Worker 异常结束时，普通执行异常沿用每个 Semantic Agent Attempt 最多一次 Automatic Invocation Recovery；准确识别为模型容量不足的异常适用下述持续恢复规则。必须已持久化可恢复的准确 Thread、没有可接受的最终 Artifact，并仍满足 ownership 与 Currentness Boundary。覆盖 timeout、非零退出、signal termination、缺少最终输出等通用执行异常，不依赖自然语言错误文案猜测业务语义。操作者停止、明确取消、Controller 退出、Thread 错配或边界无法确认时不得自动恢复；没有 Thread 的启动失败也不得自动新建 Thread。既有 Artifact 接受规则不因本决策放宽。

自动恢复使用同一 Thread 与同一 Semantic Agent Attempt，不重复计入角色预算。普通异常的一次恢复使用事实必须持久化，跨人工 Resume 保留；普通异常恢复再次失败时停止自动重试，保留 `execution_failed` 与诊断，允许维护者手动继续。恢复结果若是准确的容量不足，则进入容量等待与恢复规则，不因普通恢复额度已用尽而拒绝。自动恢复获得与原调用等长的新执行时限，从恢复调用开始计时，沿用原有效策略，不重新读取用户默认配置。

准确的 `Selected model is at capacity` 失败表示本轮被容量错误中断。只要保持相同恢复资格，就持续等待并自动 Resume 原 Thread，不设次数上限、不消耗普通异常的一次恢复额度，也不增加任何业务尝试或格式修复额度。容量恢复保留原 model、reasoning effort、checkout、工作步骤与成果，不自动切换模型或新建 Thread。若错误转为普通异常，回到普通异常规则；用户明确停止或 Executor 自身消失时遵守对应停止和对账边界。“不限次数”不表示并发启动 Worker 或立即无间隔重试；每次容量失败后固定等待 30 秒再自动续接（Q10 已确认）。

容量识别以准确失败事件为依据，不能只因桌面横幅、退出码 1、任意 HTTP 429 或账户 usage limit 而进入持续恢复。已核验本机 Codex 0.151.0 与 0.153.4 的该错误携带 `codex_error_info=server_overloaded`；应保留可取得的机器诊断，并在实际接口不暴露机器字段时针对已核验的准确容量文案处理。不能推断其他所有 `server_overloaded` 表现均获得无限恢复授权。证据见 [容量错误调研](../research/2026-09-08-codex-model-capacity.md)。

恢复必须保留中断步骤的任务与权限。角色任务中断时继续该角色任务；JSON 格式修复中断时，只续接同一 Thread 的 JSON 修复，携带原校验错误、保持 checkout 只读，不能重新进入开发或开放写权限。默认人工同 Thread Resume 也遵守此规则。

格式修复与进程自动恢复分别计数：正常输出后的格式修复仍最多两次；中断续接继承已用次数，不重新获得两次额度。最后一次格式修复在结果返回前因普通异常中断时，仍可消耗尚未使用的普通自动恢复额度续完该次修复；因容量不足中断时则按持续恢复规则续接，不消耗普通异常额度。返回结果仍不合法则停止，不分配第三次格式修复。

两次格式修复均正常返回但结果仍不合法时，不属于进程中断。本次异常恢复不改变该场景的预算或新增授权规则；先前 Q8 关于人工重新授权两次格式修复的讨论移出本次范围。

`status/history` 必须使用相同的 Host 活性事实，避免一处显示已退出、另一处仍要求等待。确认执行者已退出且有可信结束时间时显示实际耗时；没有可信结束时间时显示“执行已中断，等待恢复”、开始时间与“实际执行时长未知”。Host 无法核实时显示“运行状态无法确认”，不推断失败，也不继续累计活跃耗时。查询不得补写猜测的结束时间、修复持久状态或触发恢复；缺少 `ended_at` 时，不得把查询时刻当作实际结束时间。

## 取舍与既有决策

直接复用当前 Resume 的完整角色 Prompt 与新格式额度，会重新开放开发权限并扩大格式重试；一律拒绝格式修复中的自动恢复又会丢失有界续接的价值。因此选择持久保留中断步骤与分别计数，而不把所有失败都视为重新执行角色任务。

本 ADR 窄幅修订 ADR 0003、0009 以及 ADR 0010 延续的“不自动重试”规则，增加 Executor 存活时普通异常的一次 Worker 恢复，以及准确容量错误的不限定次数恢复。它要求默认人工 Resume 续接中断的 JSON 修复步骤；显式替换 Thread 不属于这里的默认同 Thread 恢复。Executor 自动重启、主机重启后自动重放、未知 Publisher 写入重放仍不允许。语义 Attempt 计费、Currentness、角色权限与 Publisher authority 的其他边界不变。

## 验证要求

沿用 #156 的公开 CLI、Fixture Agent 与 Fake Host 测试。覆盖 Executor 已退出、Host unknown、Task Control 缺失或损坏时的只读展示与确定性对账；无真实结束时间时，多次查询不得制造增长的活跃耗时或“无需操作”的错误提示。

恢复测试覆盖角色任务与 JSON 修复的不同中断位置、最后一次修复中断、普通自动恢复再次失败、人工续接，以及连续多次容量失败后在原 Thread 完成工作。验证准确 Thread、只读权限、校验错误传递、持久次数、独立时限、不改变业务预算，以及停止、取消、无 Thread、身份或 currentness 不成立时不启动 Worker。测试不调用真实 Codex、真实 systemd 或真实 GitHub 写入，不使用生产时长等待。

另须验证已接受 Resume 的意图不会因后续状态变化转成新窗口授权，重复原 Action 不重复执行；自动续接遇到 Human Blocker 或预算检查点不能解除门禁。人工预算 Resume 的提示与回执明确表达新窗口授权，容量失败以受控时钟验证等待 30 秒后续接。
