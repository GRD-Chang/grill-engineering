# Run 状态存储与提交合同

新 Run 的工作事实保存在 StateStore 根目录的 `state.sqlite3`。Run、工作对象、
Invocation 和关联历史使用同一数据库；完整 Run 字典是按需读取的投影，
不再另存或双写 `runs/<id>.json`。Task Control 继续保存原有 Action、Executor
及其对账事实；它不是第二份业务进度，也不凭数据库提交推定宿主已经退出。

## 故障归属

Ticket 的调用或保存失败由该 Ticket 的 `TicketState` 核对准确 Job、Invocation、
Semantic Attempt 和需求身份后保存，沿用提交协调并保留兄弟进度。局部暂停只限制
实际对象及其依赖；定向 resume 仍由该对象已有恢复合同处理。

Executor 级执行失败、共享凭据失效及共享 GitHub 权威刷新中的确定性错误使用
`run:<run_id>` 门禁；已确认 Session 退出后的中断记录也使用此身份。
Run 门禁阶段对应顶层失败状态，status/history 从相同
记录解释故障。当前选择不会改变故障归属，已完成对象不会获得新的故障门禁。
共享故障保留独立对象原有的人工、预算和暂停门禁；真实执行取消、退出确认与退出
后全部未完成调用的核对仍由执行生命周期负责，故障记录本身不证明 Worker 已退出。

公开生命周期排除旧 Executor/Worker 后，显式 Run 恢复在还原 Thread 前收口
Ticket 记录中仍为 `running/resuming` 的实际 Invocation，并同步对应调用历史与
准确匹配的观察投影，不重写 Run 原始故障解释。恢复从各 Invocation 的准确 pending
Attempt 取回原 Thread，包括未被选中的兄弟调用；`completed` 调用保持完成记录，
已保存返回优先由正常阶段消费。完成 Ticket 及兄弟的人工、预算、暂停门禁不被解除。

## 读取与协议边界

`load_run` 返回原始持久事实；`load_current_run` 另校验当前业务合同。
`has_run`、`list_run_ids` 和按仓库/Parent 发现共用 StateStore，不由调用方猜测文件布局。
单次 Run 投影在一致读事务中组装。查询连接使用 SQLite `mode=ro` 与
`query_only`，不修改业务事实、执行恢复动作或发送通知。

数据库协议为 `sqlite-run-objects-v2`；不兼容的旧 SQLite 协议与结构明确拒绝，
保留原文件，不迁移或补建索引。旧 JSON 只可用于发现身份，不读取、迁移或覆盖；
准确查询旧身份会报不兼容。按 Parent 创建 Run 时遇到无法确定归属的旧 JSON 也拒绝，
避免另建一个可能重复的获准执行 Run。已有 SQLite Run 的准确 ID 查询不受其他旧记录影响。

## 同步提交

同一进程、同一状态目录共享 FIFO 提交席位，最多容纳 128 个在途或等待请求，
等待最多 60 秒。等待发生在 Control 锁、Run 锁和数据库事务之外；不用额外线程、
服务或消息队列。取得席位后进入原 Task Control transaction，重新核验 Action、
Executor ownership/generation、Run 绑定及 Stop/Abandon 栅栏。
调度轮询使用已读取的快照预检 FIFO 补位；队列不需要变化时不发起保存请求。
预检只操作独立队列副本；需要变化时仍进入上述入口重读最新事实及授权，
不以旧快照覆盖新租约、角色或兄弟工作。进入补位提交后调度器再次读取；
无变化预检沿用本轮观察，实际租约取得仍独立重读和重验。

随后在 Run 锁下开启真实数据库写事务。读取最新事实、核验相关对象身份、修改 Job、
Attempt、Invocation、预算、门禁和历史，并一起提交。异常一起回滚；事务体不自动重试。
`update_run(run_id, update)` 提供共享的最新状态对象迁移入口：callback 只校验和修改
所属对象，StateStore 校验关联业务合同，返回持久投影。现有 Ticket 归并路径和
`save_run` 字典桥接沿用同一提交入口，不能用旧整 Run 投影覆盖兄弟对象。

Ticket 开发、审核、返回消费、工作准入与运行中的定向 Stop/Resume 使用
`load_work_run` 读取相关工作，再通过同一提交入口差量保存。Invocation 历史按
所属 Ticket 和 Resume successor 引用读取，保留原全局位置；未加载的兄弟对象
不会进入脱敏、复制、编码或覆盖。当前 Job、需求及共享工作和集成队列共同用于
核验关联合同。SQLite 内的历史索引、逻辑大小和对象材料引用随实际事实共同提交，
不是另一套业务状态；完整查询仍从相同数据库组装完整 Run。
Parent 对象投影和 Ticket 工作投影各有派生的定位、大小及引用索引；任一保存入口
在同一事务内同步两套索引，交替提交和重开查询仍读取相同的真实对象。
Job 的当前字段与历史分别编码；其字段摘要按物理对象节点的准确路径、类型和内容
组合，并仅更新变化节点的贡献。未加载的审核历史保留原节点与引用，不为刷新当前
Job 重新展开历史。Invocation 与 timeline 仍按原全局位置维护内容摘要及大小证明。

Ticket Job 的已完成 Attempt、旧预算窗口、人工阻塞、发布重试及 Thread 历史
与当前调度事实分开保存。本票读取自己的历史；兄弟历史保持未加载，仅读取必要
关联及同一 SQL 快照内的大小、条数元数据。工作投影的合同校验明确限定这些
未加载字段及其准确拥有者，仍检查当前预算、角色、候选与控制事实；完整查询
继续校验全部历史。工作校验作用域退出后不保留预算豁免，投影也不能替代提交时
对最新 SQL 事实和执行授权的重验。未加载档案不能由稀疏更新替换或清空。
本票内存投影的校验作用域绑定该次读取；额外读取不会改写旧投影的作用域。
普通字典或 JSON 树复制不携带此私有元数据，随后按完整合同校验。
公开 Ticket 交付与定向 Resume 返回完整查询，内部调度和监督显式保留工作投影。
兄弟发布重试需要已完成的 Publication Attempt 时，按角色、当前 ordinal 和
实际历史位置只读取该记录及材料引用，不把它伪装成部分历史列表。关联索引与
对象同事务保存，完整查询核验索引对应的实际历史；待处理的 Publication Attempt
继续使用当前 Job 上的原记录。
当前节点读取从排除 Ticket Attempt 子节点的索引进入，再按本票历史及必要关联
范围读取，避免先扫描全部兄弟历史路径再过滤。

取得保存席位后独立核验当前本票 Stop、Job、Invocation、需求、Generation 及
调用持有的准确租约。已释放 Agent 租约的阶段消费仍核验 Job 和 Attempt；
失败或暂停收口可以保存原对象的退出事实，正常迟到返回不能越过本票 Stop。
阶段推进时的本票 Stop 观察只读取请求映射、本票值及其必要材料引用；每次核验
当前协议、结构、Run 存在和大小界限，不加载执行或历史正文。该观察只决定是否
进入暂停路径，保存时仍重新核验最新工作事实、控制和租约，不以观察结果授权。
保存等待不重新调用 Agent，持久 `returned_result` 沿用原阶段消费和预算记账。
每票的关键 timeline 变化绑定实际提交的 Ticket，不随当前选择对象改变归属。
Agent 或 Reviewer 要求人工介入时，事件保留 `ready_for_human` 语义及原始审核
证据；其他暂停仍使用自身原因，不借用当前选中 Ticket 的人工阻塞状态。

`commit_admission()` 供已有“Control 对账包含 Run 保存”的复合路径先取得席位；
同一 StateStore 的内层保存复用席位。Action application receipt 在业务事务中保存，控制面按原准确
receipt 对账；不另建批准或恢复授权。Git、GitHub、Agent 和宿主操作必须在数据库事务外。

Parent 与普通运行控制通过 `ObjectStateStore` 读取当前对象投影并提交相关变化，
不进入 `save_run` 的完整字典桥接。当前 Invocation 与 Resume successor 的历史记录
按已有 `(work_subject, started_at)` 或 Resume 身份定位；归档历史留在原对象路径，
不会为日常提交重新组装。Invocation 定位、每字段逻辑大小与每对象材料依赖是派生索引，
不保存第二份工作状态，与原对象在同一事务内更新。
字段大小证明绑定原节点编码、内容摘要与真实子节点数；材料回收前核对准确引用数，
损坏的派生索引不能降低逻辑大小或删除仍被引用的证据。

普通控制投影只读取当前 Ticket、工作租约、集成队列与 holder 所关联的对象，
并按变化的 Ticket key 提交。Controller 需求刷新、调度与公开 Action 授权接纳边界
显式读取当前调度对象，保留兄弟门禁与恢复授权；退役 Job 和 Invocation 归档不参与。
Requeue 的新增退役记录直接追加，Parent 结构退役与当前 Job 移除在同一事务保存。

Parent 内部读取排除 Ticket Job、Ticket Invocation 与退役对象；其关联合同明确使用
Parent 验证范围。完整 Parent 在审核、发布及准确成果核验边界另读 Ticket 完成证据，
这些证据不参与 Parent 保存。预算继续保存在原 Job 或 Run Acceptance，Repair 不复制额度。
Controller 的事实刷新读取调度和当前对象；对象基线与 Action/代次授权共同核验，
被替换的 Job、Generation 或 Invocation 不能由迟到结果覆盖，兄弟对象变化不被旧投影抹掉。
外部等待按明确字段及修改前的 Action receipt、停止与需求事实提交；cleanup 只保存自身事实，
Ticket lane 的清理仍在其所属对象事务中合并。所有提交保留同源 timeline 解释。
Driver 等待同时保存 Run 窗口与准确 Ticket 的 `external_wait`，核对原 Job、Invocation
和授权；调度选择为 active 时按同一 lane 等待事实比较，不覆盖 Run Stop 等全局门禁。
cleanup 对账边界另读完整 Ticket Completion 证据，以补登记完成后、清理登记前中断的对象；
这些完成证据不参与 cleanup 保存。

对象投影携带仅在内存中的基线，stdout reader 线程回调沿用同一准确基线；
每线程的备用缓存只保留一个当前 Run，外层事务回滚使基线失效。
公开生命周期 Action 返回完整查询结果，Engine 的内部阶段和保存不以完整历史为工作输入。
`load_run` / status / history / 导出继续按一致读事务组装完整持久事实。

observer 只在持久提交且释放提交席位、数据库及 Control/Run 锁之后调用。
observer 失败记录日志，保存仍成功，不重放事务或外部动作。故障注入的
`_after_run_saved` 也在持久提交后运行，其崩溃信号保留测试语义。
通知沿用 History 的 Attempt 关联、结果证据和执行时长，只省去通知不显示的预算
呈现与支撑记录列表计算；完整 History 查询继续包含这些明细。
启用通知时，Executor observer 在此锁外边界读取完整持久事实，保留兄弟门禁与
已完成 Ticket 的解释；该查询不成为业务提交的基线，也不另存展示状态。

Worker 沙箱遮蔽状态根目录及数据库、WAL/SHM 和控制锁，只重新开放本次工作区及
只读 Git 元数据；启动后新出现的日志文件也不能暴露程序权威。

## 证据、历史与成本

普通对象按稳定路径保存，只写变化节点。固定需求、Review Context、Prompt resources
等快照及至少 1024 UTF-8 字节的字符串按完整内容 SHA256 身份存一次，其他位置引用。
Ticket Job、当前和历史 Invocation、timeline 事件各自使用对象路径及内容引用，
不逐项拆成标量行；对象变化时替换该路径的引用，内部固定审核材料仍独立去重。
这沿用同一 SQLite 协议，原有节点投影在下一次工作迁移前也能直接读取。
身份覆盖实际内容，不用标题或当前选择对象认领证据。材料引用与对象变化同事务提交；
本次移除引用后无任何引用的材料在写事务中回收，仍被其他 Run 或审核历史引用的材料保留。

沿用 timeline 256 条、continuation 256 条、diagnostics 32 条及每条 16 KiB 上限。
Invocation 保留全部身份、结果、Thread、绑定、Attempt、Review Context 和 Resume 关系。
最近 256 条保留执行分段与等待详情；更早且已结束、没有当前 Invocation 或 pending
Attempt 引用的分段/等待数组压缩为条数和 SHA256 摘要，不截断恢复或审核需要的材料。
对象提交只检查刚移出详细窗口的 Invocation，以及当前绑定或 pending Attempt 释放的
准确历史记录；定位后沿用同一条记录的压缩规则，不扫描全部历史。
执行时长保留已证明的汇总与完整性，原来未知的时长仍为未知。读取损坏列表时先核验
真实子节点，再分配数组，不从损坏的长度字段预分配内存。
每 Run 的完整逻辑投影仍受 4 MiB 限制，包含材料展开后的成本；超限拒绝新提交，
保留原提交，不通过删除关键证据腾出空间。

完整创建、显式完整投影保存与尚未接入对象提交的路径仍可使用字典桥接，
桥接会读取、脱敏、比较完整投影，列表移位也会更新多个位置节点。
完整保存只为源子树变化的字段重新生成大小证明，仍核验旧字段证明和历史身份索引。
同一写事务已有准确完整读取视图时，历史摘要和大小按变化的位置更新；实际写入后
以完整字段证明再次检查逻辑大小，超限原子回滚。首次创建和无该视图的保存仍先检查完整值。
Parent 与普通运行控制不使用此桥接；完整查询不是日常对象提交的基线。普通查询和写入连接仅在单次边界持有，成功、失败均关闭。
对象读取按有界批次查找准确子树，调度所需完整集合不重复读取其子集。
同一一致读取内共用已核验的材料原文，返回容器仍独立，下一次读取重新核验实际字节。
工作读取的实际 TEXT 在严格 UTF-8 解码后，若与已有有界完整视图中同材料身份的
原文逐字一致，可复用该原文的 SHA256 证明；新身份或任何文字变化都重新计算 SHA256。
它不复用 SQL 类型、实际长度、Run 链接、对象引用或写入授权的检查结果。
有界工作读取在同一事务内获取对象及其准确材料闭包；先按实际字节核验聚合上限，
通过后才按材料身份排序，把 UTF-8 正文拼为一次性 BLOB，并按相同顺序读取身份、
长度、Run 引用及原始 SQL 类型元数据。逐份按实际字节边界恢复正文，重新核验
SHA256、声明与实际长度、TEXT/INTEGER 类型及准确引用，保留 NUL、多字节字符、
空文本和非规范 JSON 原文。超限或缺少 JSON 函数时沿用原稀疏读取；该 bundle
仅用于本次传输，不持久保存或缓存。
完整小 Run 查询也用原始 BLOB 和类型元数据传递材料，避免在 observer 查询中
反复转义大正文。已有完整读取视图的内容比较包含实际字节及全部类型、长度元数据；
同字节的 SQL 类型变化不能命中旧视图。SHA256 与准确引用仍由完整读取路径核验，
超限和缺少 JSON 函数时保留原逐行路径。

`save_run` 字典桥接仍会读取、脱敏、比较完整投影；
Ticket、Parent 与普通运行控制的日常提交不使用这条桥接。整体查询、导出和通知观察按需读取完整事实，
均不复用其结果作为执行授权。普通查询和写入连接仅在单次边界持有，成功、失败均关闭。
一次 Ticket 交付可在当前线程内复用各一个只读和写入连接，以复用 SQLite 准备语句；
每笔读取仍开启新快照并重新校验结构、协议与实际事实，每笔写入仍独立开启、提交
或回滚事务并清除事务视图。空闲连接不持有事务；数据库被移除或替换时关闭旧连接，
交付成功、暂停或异常退出时关闭该次作用域的全部连接，不建立长期连接池。
监督轮询先核验当前 Run 状态及集成拥有者、队列的实际小节点；仅在明确正常状态
且没有拥有者、队列为空时跳过整工作读取。存在候选、控制门禁或其他状态时沿用
原工作读取与拥有者选择。完成回调复用同一只读观察连接检查新队列事实；版本或
数据库身份变化仍触发重读，不以观察快照代替提交授权。
调度循环另有一个限定作用域、仅当前线程使用的只读观察连接，退出循环时关闭。
队列提交另复用同线程、同调度作用域的写连接；每次仍单独开启并提交真实事务，
重新核验数据库文件身份、结构及持久化配置，退出时关闭连接。
它在两次轮询间不持有事务，也不用于业务写入或授权。
默认工作读取已按本次实际材料计算投影大小，调度只复用该次的标量结果决定有界
保留；自定义读取入口仍检查实际返回值，不重复编码已检查过的默认投影。
同一个写事务内复用一次已校验的读取视图，每次返回独立可变副本；写入使视图失效，
未变化对象复用该事务中已核验的编码及完整材料依赖，提交或回滚后释放事务视图。
内部队列与 Ticket 提交可借用该事务已经隔离的原始基线作只读比较；默认读取、
合同验证与基线交接在同一内部入口完成，调用方修改只发生在交接之后。仍核验准确
Run、实际 SQL 变更计数和当前投影，调用方变更自己的独立树。普通保存及自定义视图
继续复制基线，不向事务外认领旧授权；内容无变化的元数据不制造 SQLite 新版本。
工作视图复用还要求准确 Run、Ticket、连接的 SQL 变更计数一致；直接 SQL 修改
同样使视图及解码上下文失效。每次读取仍核验当前结构与协议，实际控制授权独立重验。
变化对象只把自身完整引用闭包对应的材料交给写入校验，未变化事件的材料不重复写入。
timeline 及 continuation 按实际变化位置编码并计算逻辑大小差；普通追加不重新
编码旧事件，容量移位仍处理各个发生变化的位置。原位置对象及材料来自该事务
已校验的视图，直接 SQL 变更使保存基线失效，不能借旧对象掩盖当前缺失。
TicketState 可显式请求不展开共享 timeline：本次根长度、连续事件节点及无子节点覆写的
形状必须准确，所有材料及完整引用必须重新通过校验。事件规范文本可来自本次完整恢复，
或材料再次证明的已有有界视图；增加事件不使其他已证明的事件失效。工作合同只在上述
当前证明完整时记录字段未加载；证明不足仍完整读取，不以空数组代替旧证据。
追加使用真实末事件，continuation 满容量
时移动已校验的位置对象及引用，按被移除事件与新事件的规范字节数更新原总大小。
公开完整查询、通知观察者与普通 StateStore 调用仍读取全部 timeline。
只使用当前业务事实的调度与队列提交也使用上述 timeline 范围证明；证明不足仍完整恢复。
局部对象恢复对本次直接材料身份按最多 256 项预取，先检查实际正文总量；
超过 512 KiB 或缺少 JSON 函数时继续原按需读取。批次与嵌套材料都核验真实 Run 链接、
类型、UTF-8 长度与 SHA256，不在不同读取之间保留材料内容。
工作对象写入按所属路径批次释放和添加引用，现存材料必须与本次生成的准确原文、
类型及长度相同；含 NUL 或大正文使用原绑定路径。回收仍同时检查其他 Run 的引用，
整个批次处于原授权事务中，任一失败回滚全部变化。
兄弟对象变化后的重建也可以复用已知快照的准确 JSON 编码；此前必须重新核验本次
完整材料内容、UTF-8 长度及 SHA256，且原快照的所有传递依赖仍存在。
下一事务与公开查询重新读取 SQLite 的完整节点和材料，包括材料长度及节点类型；
完整查询核对本次实际材料后复用已证明的快照引用集合；未覆盖的快照按原路径恢复，
实际引用行仍在同一 SQL 快照内完整读取并严格比对。
完整重建时，某字段的全部源节点与已有有界视图准确一致，且快照依赖已由本次
材料校验重新证明，才直接解码已有字段编码；其他字段仍逐节点组装，不增加缓存。
工作投影的大小计算也可复用此前完整查询产生的规范 JSON 编码，但必须重新证明
本次对象身份和完整依赖相同，排除被子节点覆写的快照；局部 Invocation 历史不能
直接使用完整数组编码。所选记录的当前索引和引用全部校验后，可按真实所选位置顺序
拼接各记录已证明的规范文本，用于该局部数组的大小计算和独立基线复制。
新恢复的快照在本次读取中只生成一次规范 JSON 编码；完整对象引用校验通过、
没有子节点覆写时，该编码也用于后续大小计算和隔离基线复制，不写入额外持久状态。
其他字段仍重新编码；材料原文的非规范数字、转义或空白不能使大小校验低估。
同样的本次材料证明可用于直接解码已有规范快照文本；每个返回节点与内部恢复基线
分别拥有独立容器，归档子节点覆写及调用方修改不会污染下一次读取。
只有实际 SQL 内容完全一致才复用投影重建结果，不按时间戳或本地 revision 判断。
每个 Repository 最多保留一个重建结果，逻辑 JSON 和物理引用表示均不超过 512 KiB
才入选；大投影不保留。返回值始终独立，数据库结构与协议在每个新事务中重验。
结构校验每次读取完整 `sqlite_master` 定义和当前 protocol；定义完全一致时复用其
列、主键和外键校验结果，最多保留 16 组、每组 SQL 文本不超过 16 Ki 字符。
增删表、列、外键、trigger/view 或更改 protocol 都不能由缓存绕过。
不可变节点路径和标量的解析各最多复用 4096 项，每项编码不超过 256 字符；
字段大小证明的纯哈希计算最多复用 4096 项，字符串参数合计不超过 512 字符；
复用依据为完整实际参数，每次仍读取并检查源节点、索引和总大小，不复用数据库校验结论。
准确 JSON 的标量和路径编码也各最多复用 4096 项。字符串及路径原始文本不超过
256 字符，路径最多 16 段，整数最多 128 bits；浮点值不缓存，bool 与 int 分开认领。
它们按完整实际内容认领，不缓存数据库身份或可变对象。
执行时间的 ISO 文本解析最多复用 2048 项，每项输入最多 128 字符，结果为不可变
datetime；替换解析实现或输入超限时沿用原路径。实际 Invocation 时间仍来自本次读取，
不复用状态、执行授权或时间预算判定。
小投影优先在 SQL 内聚合实际节点与材料行，减少逐行游标的线程切换；
缺少 SQLite JSON 函数时回到逐行读取，不增加依赖或数据库协议。
批量写入遇到含 NUL 的原始字符串时使用参数绑定，避免旧 SQLite JSON1
解码截断文本；其他批次继续使用有界 JSON 传输，材料长度与 SHA256 校验保持不变。
聚合结果只用于一致读取及实际内容比较，不持久保存完整 Run JSON。
工作查询在同一读事务内分开读取有界对象及其准确材料依赖，有限子结果使用物化边界，
避免优化器重复展开和编译；
物化边界只属于本条 SQL。SQLite 3.35 以前沿用无提示查询。超出聚合预算的材料只参与
实际大小预检，不放进临时物化结果的正文，随后由有界逐行路径读取或拒绝。
材料联接从本次准确引用开始，按材料主键查找；旧版优化器不能改为扫描所有 Run
的材料，使无关历史增长进入本票读取成本。
普通 Ticket Stop 与空监督预检可在一次有界 SQL 中读取实际 schema/protocol、大小、
准确节点及子节点存在性；仍逐项检查原形状和类型。正文先在物化前限制大小，
材料、复杂编码、非规范 DDL 或缺少 JSON 函数时沿用原结构与材料读取路径。
局部集合的两级映射子树和关联 Invocation 历史按准确所选路径批读，保留各记录
实际身份声明和独立容器；提交中已读的子树不重复查询，不扩大到未选兄弟对象。
创建器的准确表定义匹配时，小 Run 的全部 DDL、protocol、大小、节点和材料由一条
SQL 一致读取；非标准但兼容的定义、大 Run 或缺少 JSON 函数时仍使用显式读事务。
大小条件先于内容聚合，损坏或超限的物理表示不会被无界聚合。
工作查询也在实际对象读取中核对全部准确表、索引定义与唯一 protocol；非标准但兼容
的定义仍走原结构检查与稀疏读取。完整读取始终以原始 SQL 类型核对当前索引，
BLOB 值不能借 JSON 文本的兼容行为冒充原始 TEXT。
入选的重建结果同时保留容器字段的有界 JSON 编码，返回时逐字段解码独立副本；
大投影仅复制已校验 JSON 树的容器并共享不可变标量，避免通用 deepcopy 的逐叶开销。
默认 `load_current_run` 的纯业务合同检查可复用同一函数对同一不可变存储视图的
成功结果。视图必须已由本次完整 SQL 内容证明，或属于当前写事务的已校验基线；
标记只保留弱引用，不额外持有旧 Run，返回值仍为独立副本。内容、校验函数或
自定义读取/校验入口变化时重新检查；失败结果及大投影不缓存。
这不复用执行授权：Action、Executor ownership/generation、Stop/Abandon、对象
归属与预算迁移条件仍由实际提交入口独立核验。
逻辑大小按顶层字段使用 JSON 编码器计算 UTF-8 字节数，包含每次材料展开，
避免逐 token 编码和额外的完整 Run JSON 字符串。已有完整快照编码可以直接组装
相应字段；存在另存的覆盖子节点时仍按最终组装内容计算，不能漏计或丢失字段。

调度观察只复用该循环已经验证的只读投影，不向其他调用者共享可变字典。
每次轮询在同一个只读连接查询 SQLite `PRAGMA data_version`；任意其他连接或
进程的提交、结构或协议变化都会触发完整读取和合同校验。版本在读取前采样，
读中发生的提交不能被标成已观察；文件移除或替换也会使观察失效。
仅逻辑投影不超过 512 KiB 才保留，较大投影每次重读。它不复用进程自造 revision，
不在轮询间保留读事务，不改变 Stop/Resume 栅栏或提交时的独立授权重验。

写入差异按最多 256 行一批处理，估算 UTF-8 输入不超过 64 KiB 时使用 SQLite JSON
函数传递该批具体行；更大的材料使用原 executemany。这个临时传输不持久保存。
缺少 JSON 函数时退回原逐行写入；约束或其他错误不重试，全部批次和材料引用仍在
原事务内一起回滚。GC 仍查询实际引用，不能只凭缓存猜测材料已不再使用。

实现使用 Python 标准库 SQLite，采用 FULL 同步与 WAL 事务日志。WAL 只暴露完整
提交；崩溃后只读连接可读取最后提交，SQLite 的共享索引与锁文件属于内部协调材料，
不构成另一份 Run 权威。正常关闭连接由 SQLite 管理 checkpoint 和协调文件回收，
程序不在查询中删除日志或猜测恢复业务状态。

设计依据：[Python sqlite3 事务与只读 URI](https://docs.python.org/3/library/sqlite3.html)、
[SQLite 隔离](https://www.sqlite.org/isolation.html)、
[SQLite WAL](https://www.sqlite.org/wal.html)、
[SQLite JSON 聚合](https://www.sqlite.org/json1.html)、
[SQLite WITH 物化边界](https://www.sqlite.org/lang_with.html)、
[SQLite data_version](https://www.sqlite.org/pragma.html#pragma_data_version)。这里复用这些本地事务机制，
不引入 ORM、事件溯源、独立持久服务或历史 Run 迁移。
