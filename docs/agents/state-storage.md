# Run 状态存储与提交合同

新 Run 的工作事实保存在 StateStore 根目录的 `state.sqlite3`。Run、工作对象、
Invocation 和关联历史使用同一数据库；完整 Run 字典是按需读取的投影，
不再另存或双写 `runs/<id>.json`。Task Control 继续保存原有 Action、Executor
及其对账事实；它不是第二份业务进度，也不凭数据库提交推定宿主已经退出。

## 读取与协议边界

`load_run` 返回原始持久事实；`load_current_run` 另校验当前业务合同。
`has_run`、`list_run_ids` 和按仓库/Parent 发现共用 StateStore，不由调用方猜测文件布局。
单次 Run 投影在一致读事务中组装。查询连接使用 SQLite `mode=ro` 与
`query_only`，不修改业务事实、执行恢复动作或发送通知。

数据库协议与结构不兼容时明确拒绝。旧 JSON 只可用于发现身份，不读取、迁移或覆盖；
准确查询旧身份会报不兼容。按 Parent 创建 Run 时遇到无法确定归属的旧 JSON 也拒绝，
避免另建一个可能重复的获准执行 Run。已有 SQLite Run 的准确 ID 查询不受其他旧记录影响。

## 同步提交

同一进程、同一状态目录共享 FIFO 提交席位，最多容纳 128 个在途或等待请求，
等待最多 60 秒。等待发生在 Control 锁、Run 锁和数据库事务之外；不用额外线程、
服务或消息队列。取得席位后进入原 Task Control transaction，重新核验 Action、
Executor ownership/generation、Run 绑定及 Stop/Abandon 栅栏。
调度轮询使用已读取的快照预检 FIFO 补位；队列不需要变化时不发起保存请求。
预检只操作独立队列副本；需要变化时仍进入上述入口重读最新事实及授权，
不以旧快照覆盖新租约、角色或兄弟工作。进入补位提交后调度器再次读取；
无变化预检沿用本轮观察，实际租约取得仍独立重读和重验。

随后在 Run 锁下开启真实数据库写事务。读取最新事实、核验相关对象身份、修改 Job、
Attempt、Invocation、预算、门禁和历史，并一起提交。异常一起回滚；事务体不自动重试。
`update_run(run_id, update)` 提供共享的最新状态对象迁移入口：callback 只校验和修改
所属对象，StateStore 校验关联业务合同，返回持久投影。现有 Ticket 归并路径和
`save_run` 字典桥接沿用同一提交入口，不能用旧整 Run 投影覆盖兄弟对象。

`commit_admission()` 供已有“Control 对账包含 Run 保存”的复合路径先取得席位；
同一 StateStore 的内层保存复用席位。Action application receipt 在业务事务中保存，控制面按原准确
receipt 对账；不另建批准或恢复授权。Git、GitHub、Agent 和宿主操作必须在数据库事务外。

observer 只在持久提交且释放提交席位、数据库及 Control/Run 锁之后调用。
observer 失败记录日志，保存仍成功，不重放事务或外部动作。故障注入的
`_after_run_saved` 也在持久提交后运行，其崩溃信号保留测试语义。

Worker 沙箱遮蔽状态根目录及数据库、WAL/SHM 和控制锁，只重新开放本次工作区及
只读 Git 元数据；启动后新出现的日志文件也不能暴露程序权威。

## 证据、历史与成本

普通对象按稳定路径保存，只写变化节点。固定需求、Review Context、Prompt resources
等快照及至少 1024 UTF-8 字节的字符串按完整内容 SHA256 身份存一次，其他位置引用。
Ticket Job、当前和历史 Invocation、timeline 事件各自使用对象路径及内容引用，
不逐项拆成标量行；对象变化时替换该路径的引用，内部固定审核材料仍独立去重。
这沿用同一 SQLite 协议，原有节点投影在下一次工作迁移前也能直接读取。
身份覆盖实际内容，不用标题或当前选择对象认领证据。材料引用与对象变化同事务提交；
本次移除引用后无任何引用的材料在写事务中回收，仍被其他 Run 或审核历史引用的材料保留。

沿用 timeline 256 条、continuation 256 条、diagnostics 32 条及每条 16 KiB 上限。
Invocation 保留全部身份、结果、Thread、绑定、Attempt、Review Context 和 Resume 关系。
最近 256 条保留执行分段与等待详情；更早且已结束、没有当前 Invocation 或 pending
Attempt 引用的分段/等待数组压缩为条数和 SHA256 摘要，不截断恢复或审核需要的材料。
执行时长保留已证明的汇总与完整性，原来未知的时长仍为未知。读取损坏列表时先核验
真实子节点，再分配数组，不从损坏的长度字段预分配内存。
每 Run 的完整逻辑投影仍受 4 MiB 限制，包含材料展开后的成本；超限拒绝新提交，
保留原提交，不通过删除关键证据腾出空间。

本阶段字典桥接仍会读取、脱敏、比较完整投影，列表移位也会更新多个位置节点；
它不代表所有日常路径已达到只处理相关对象的成本目标。后续路径接入上述同一合同，
不再建立另一套读写约定。普通查询和写入连接仅在单次边界持有，成功、失败均关闭。
调度循环另有一个限定作用域、仅当前线程使用的只读观察连接，退出循环时关闭。
它在两次轮询间不持有事务，也不用于业务写入或授权。
同一个写事务内复用一次已校验的读取视图，每次返回独立可变副本；写入使视图失效，
未变化对象复用该事务中已核验的编码及完整材料依赖，提交或回滚后释放事务视图。
兄弟对象变化后的重建也可以复用已知快照的准确 JSON 编码；此前必须重新核验本次
完整材料内容、UTF-8 长度及 SHA256，且原快照的所有传递依赖仍存在。
下一事务与公开查询重新读取 SQLite 的完整节点和材料，包括材料长度及节点类型；
只有实际 SQL 内容完全一致才复用投影重建结果，不按时间戳或本地 revision 判断。
每个 Repository 最多保留一个重建结果，逻辑 JSON 和物理引用表示均不超过 512 KiB
才入选；大投影不保留。返回值始终独立，数据库结构与协议在每个新事务中重验。
结构校验每次读取完整 `sqlite_master` 定义和当前 protocol；定义完全一致时复用其
列、主键和外键校验结果，最多保留 16 组、每组 SQL 文本不超过 16 Ki 字符。
增删表、列、外键、trigger/view 或更改 protocol 都不能由缓存绕过。
不可变节点路径和标量的解析各最多复用 4096 项，每项编码不超过 256 字符；
准确 JSON 的标量和路径编码也各最多复用 4096 项。字符串及路径原始文本不超过
256 字符，路径最多 16 段，整数最多 128 bits；浮点值不缓存，bool 与 int 分开认领。
它们按完整实际内容认领，不缓存数据库身份或可变对象。
小投影优先在 SQL 内聚合实际节点与材料行，减少逐行游标的线程切换；
缺少 SQLite JSON 函数时回到逐行读取，不增加依赖或数据库协议。
批量写入遇到含 NUL 的原始字符串时使用参数绑定，避免旧 SQLite JSON1
解码截断文本；其他批次继续使用有界 JSON 传输，材料长度与 SHA256 校验保持不变。
聚合结果只用于一致读取及实际内容比较，不持久保存完整 Run JSON。
创建器的准确表定义匹配时，小 Run 的全部 DDL、protocol、大小、节点和材料由一条
SQL 一致读取；非标准但兼容的定义、大 Run 或缺少 JSON 函数时仍使用显式读事务。
大小条件先于内容聚合，损坏或超限的物理表示不会被无界聚合。
入选的重建结果同时保留容器字段的有界 JSON 编码，返回时逐字段解码独立副本；
大投影仅复制已校验 JSON 树的容器并共享不可变标量，避免通用 deepcopy 的逐叶开销。
默认 `load_current_run` 的纯业务合同检查可复用同一函数对同一不可变存储视图的
成功结果。视图必须已由本次完整 SQL 内容证明，或属于当前写事务的已校验基线；
标记只保留弱引用，不额外持有旧 Run，返回值仍为独立副本。内容、校验函数或
自定义读取/校验入口变化时重新检查；失败结果及大投影不缓存。
这不复用执行授权：Action、Executor ownership/generation、Stop/Abandon、对象
归属与预算迁移条件仍由实际提交入口独立核验。
逻辑大小按顶层字段使用 JSON 编码器计算 UTF-8 字节数，包含每次材料展开，
避免逐 token 编码和额外的完整 Run JSON 字符串。已有完整快照编码可以直接组装
相应字段；存在另存的覆盖子节点时仍按最终组装内容计算，不能漏计或丢失字段。

调度观察只复用该循环已经验证的只读投影，不向其他调用者共享可变字典。
每次轮询在同一个只读连接查询 SQLite `PRAGMA data_version`；任意其他连接或
进程的提交、结构或协议变化都会触发完整读取和合同校验。版本在读取前采样，
读中发生的提交不能被标成已观察；文件移除或替换也会使观察失效。
仅逻辑投影不超过 512 KiB 才保留，较大投影每次重读。它不复用进程自造 revision，
不在轮询间保留读事务，不改变 Stop/Resume 栅栏或提交时的独立授权重验。

写入差异按最多 256 行一批处理，估算 UTF-8 输入不超过 64 KiB 时使用 SQLite JSON
函数传递该批具体行；更大的材料使用原 executemany。这个临时传输不持久保存。
缺少 JSON 函数时退回原逐行写入；约束或其他错误不重试，全部批次和材料引用仍在
原事务内一起回滚。GC 仍查询实际引用，不能只凭缓存猜测材料已不再使用。

实现使用 Python 标准库 SQLite，采用 FULL 同步与 WAL 事务日志。WAL 只暴露完整
提交；崩溃后只读连接可读取最后提交，SQLite 的共享索引与锁文件属于内部协调材料，
不构成另一份 Run 权威。正常关闭连接由 SQLite 管理 checkpoint 和协调文件回收，
程序不在查询中删除日志或猜测恢复业务状态。

设计依据：[Python sqlite3 事务与只读 URI](https://docs.python.org/3/library/sqlite3.html)、
[SQLite 隔离](https://www.sqlite.org/isolation.html)、
[SQLite WAL](https://www.sqlite.org/wal.html)、
[SQLite JSON 聚合](https://www.sqlite.org/json1.html)、
[SQLite data_version](https://www.sqlite.org/pragma.html#pragma_data_version)。这里复用这些本地事务机制，
不引入 ORM、事件溯源、独立持久服务或历史 Run 迁移。
